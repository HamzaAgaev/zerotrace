# Интерфейс ZeroTrace

React, TypeScript и Vite. Экраны показывают трассы, граф сервисов, аудит,
конфигурации, журнал и лабораторные прогоны. По умолчанию используется API
того же origin; отдельный режим demo работает с fixtures.

## Разработка

С Node.js 22 и npm:

```sh
npm ci
npm run dev
npm test
npm run build
```

Для запуска всей системы в Docker используйте [корневой README](../README.md).
Контракт HTTP описан в [API.md](API.md).

## Структура

- `src/views/` — страницы и композиция интерфейса.
- `src/components/` — общие элементы, редактор `ServiceConfig` и диалоги планов.
- `src/api/` — типы, клиент и демонстрационные данные.
- `src/presentation.ts` — общие пользовательские подписи и форматирование.
- `src/state.tsx`, `src/storage.ts` — сохранение вкладок, фильтров и черновиков.
- `src/analysis.ts` — агрегаты графа сервисов, черновик бюджета и экспорт JSON.
- `tests/` — тесты преобразований данных и контрактов.

Конфигурационные записи выполняет сервер после подтверждения плана.
Frontend не исполняет аналитические правила и не обращается к управляющим
API сервисов напрямую. Локальный «Прогноз ускорения» является предварительной
моделью и не заменяет реальный прогон.

Граф рассчитывается по загруженной выборке: максимум 100 деталей трасс,
2000 спанов на трассу и 40 узлов карты. Ошибки загрузки отмечаются в UI.


## Навигация и сохранение интерфейса

Основные разделы: «Трейсы», «Сервисы», «Аудит» и «Лаборатория».
В «Сервисах» находятся граф, статистика и настройки выбранного вызова.
Сравнение групп открывается кнопкой «Сравнить» в списке трейсов.
Старые ссылки `/graph`, `/timings`, `/policies` и `/compare` совместимы с новой структурой.

Выбор, фильтры, вкладки и черновики хранятся локально в браузере
под префиксом `zerotrace.ui.v1`, отдельно для подключения и окружения.
Состояние трейса привязано к полной ссылке с версией. Восстановление черновика
не применяет настройки и не запускает нагрузку. Серверная версия сверяется
перед подготовкой плана. Вкладки трейса также поддерживают параметры ссылки.

Правила оформления и приёмки: [требования к интерфейсу](../docs/plans/FRONTEND_UNIFICATION.md).

Явные параметры ссылки имеют приоритет над сохранённым режимом.
`#/traces?mode=compare` открывает выбор групп, `mode=list` завершает его,
не очищая группы. Старые ссылки `#/compare`, `#/graph`, `#/timings`
и `#/policies` открывают соответствующий режим независимо от сохранённой вкладки.
Состояние демолаборатории также изолировано по подключению и окружению.

## Прогноз и сравнение групп

В подключённом режиме прогноз и сравнение групп выполняет сервер. Интерфейс
передаёт точные ревизии трейсов в `POST /api/v1/projections` и
`POST /api/v1/comparisons`, отображает метрики и экспортирует серверный результат
с `analysis_id`. Локальных копий этих двух алгоритмов в UI нет. Новый выбор
отменяет предыдущий запрос; старый результат не отображается как новый.

Прогноз обновляется после изменения веток с задержкой 300 мс. Серверные причины
неприменимости и ошибки отображаются вместо числового результата. Согласование
временных отметок обеспечивает пользователь источника. Прогноз остаётся моделью,
а различия групп не доказывают причинность. В деморежиме для этих двух расчётов
предлагается подключить сервер; фиктивные результаты не подставляются.
