# Прогноз ускорения по трейсу

Интерфейс задаёт входы прогноза и отображает результат сервера. Метрики и
экспортированный результат не пересчитываются отдельным браузерным алгоритмом.

## Прогноз ускорения одного запроса

В карточке трейса откройте «Прогноз ускорения», выберите ветку вызовов и укажите,
на сколько процентов сократить её длительность. Сервер пересчитывает длительность
всего запроса с учётом последовательных и пересекающихся во времени веток.
Ускорение одной параллельной ветки может не сократить весь запрос, если другая
ветка продолжает определять время ожидания.

`POST /api/v1/projections` получает `trace_ref` с окружением, trace ID, поколением
и ревизией, а также `changes`: список `span_id` и `speedup_percent`. Опциональный
`root_span_id` ограничивает расчёт поддеревом. Результат содержит исходную
длительность, прогноз, выигрыш, кандидатов на ускорение, допущения, ограничения
и `analysis_id`. При изменении выбора UI ожидает новый ответ сервера; устаревший
ответ не становится результатом нового сценария.

Если данных недостаточно, сервер возвращает причину вместо выдуманного выигрыша.
Например, отсутствующий родитель, потерянные данные, цикл или существенно
выходящий за границы родителя дочерний интервал препятствуют расчёту.

Прогноз не выполняет приложение заново и не моделирует новую нагрузку, изменения
числа повторов, кэширование или побочные эффекты. Проверка изменения реальным
запуском выполняется в лаборатории отдельно.

## Временная шкала

Пользователь, подключающий источники, обеспечивает согласованность их временных
отметок. Прогноз и сравнение интервалов считают переданные timestamps одной
временной шкалой. Отсутствие или различие `clock_domain` не означает автоматический
отказ и не заменяется придуманной меткой часов. Исходные timestamps сохраняются.
Это допущение модели, а не результат измерения или автоматической синхронизации
часов ZeroTrace. Невозможные фактические границы всё равно проверяются.

## Проверка изменения в лаборатории

Отдельного экрана для сравнения произвольных групп трейсов нет. Чтобы проверить
эффект изменения настройки, используйте лабораторное сравнение прогонов: оно
сопоставляет зафиксированные выборки до и после изменения с учётом сценария,
сбоя, нагрузки, seed и снимков конфигураций. Это контролируемая проверка, а не
сравнение произвольно выбранных групп наблюдаемого трафика.

## Воспроизводимость результата

Прогноз привязан к точной ревизии трейса и сохраняет `analysis_id`. Скачанный
из интерфейса JSON содержит серверный результат. Подробности API приведены в
[операторском руководстве](operations.md).

## Что изменилось

Прогноз ускорения рассчитывает сервер. Интерфейс передаёт точные ревизии трейса,
отображает ответ и экспортирует его; отдельный экран сравнения произвольных групп
удалён.

Раньше серверный прогноз отказывал обычным OTLP-трейсам без подтверждённого
`clock_domain`. Теперь согласованность timestamps — явное допущение, за которое
отвечает пользователь источника. Проверки структуры и фактических границ
сохранены. Версии алгоритмов повышены до `interval-blocks-v1.1.0` для прогноза
и `1.1.0` для групп, чтобы результаты с разными допущениями различались.

При изменении входов интерфейс отменяет предыдущий запрос и скрывает устаревший
результат. Отрицательная разница медиан принимается корректно: группа B может
оказаться быстрее A. В режиме локальных демоданных предлагается подключить
сервер, а вычислительная подстановка не выполняется.

## Как проверяется интеграция

- [Тест публичного API](../../backend/tests/analytics/test_common_analytics_api.py)
  проходит от HTTP OTLP-приёмника без clock metadata до числового прогноза.
- [Серверные тесты прогноза](../../backend/tests/analytics/test_projection.py)
  проверяют математику, параллельные интервалы и качество данных.

Для проверки работающего приложения откройте прогноз по настоящему трейсу,
добавьте ветку и убедитесь, что отправлен `POST /api/v1/projections`. Скачанный
JSON должен содержать тот же результат и `analysis_id`, что вернул API-запрос.
Полные команды автоматических проверок приведены в
[руководстве по тестированию](../development/testing.md).
