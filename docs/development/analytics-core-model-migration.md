# План миграции аналитики (C) на `core/model.py` (B)

Статус: план, к выполнению **после демо**. Владелец выполнения: Амир (C),
поддержка: Миша (B). Каждый шаг — отдельный коммит/PR, откатываемый
независимо. Ни один шаг не меняет поведения: сначала фиксируем выводы,
потом меняем реализацию, сравнение выводов — ворота качества.

## Цель и не-цели

**Цель:** единая каноническая семантика per-edge статистики и доверия к
конфигу, типизированная вместо соглашений о строковых ключах.

**Не-цели:**
- Не переписываем `flatten_policies` (merge P4-снимков, capabilities,
  external_timeouts) — он остаётся; `build_edge_policy` принимает его вывод.
- Не трогаем `Comparison`/`projection`/`evalkit` — там своя логика когорт.
- Не меняем wire-форматы ответов аудита: находки, evidence, оценки
  правил сериализуются как сейчас.

## Шаг 1. Слой доверия к политике: call-сайты → типизированный `EdgePolicy` — ВЫПОЛНЕНО

**Сделано (Миша, 2026-11-11):** `_operand` в `core/model.py` воспроизводит
семантику `sourced_value` один-в-один (сверка ревизий операнда со снимком;
плоские операнды читаются по источнику снимка независимо от свежести;
форма операнда маркируется в `reasons`). Добавлены `trusted_value` /
`trusted_int`. Пять call-сайтов переведены:

| Файл | Было | Стало |
|---|---|---|
| `rules/budget.py` `retry_budget` | `sourced()` ×4 по ключам | `build_edge_policy` + `trusted_int` (max_attempts, per_attempt_timeout_ns); `budget_ns`/`backoff` — канонический `sourced_value` (вне typed-вида) |
| `rules/diagnostics.py` R7 | `sourced(retry_on) if current` | `sourced_value(...)` через `is_current_policy` (список вне typed-вида) |
| `rules/diagnostics.py` R8 | `sourced()` ×2 | typed `per_attempt_timeout_ns` + `sourced_value(upstream_per_attempt_timeout_ns)` |
| `rules/audit.py` R3 | `current()` + `sourced(max_attempts)` | `is_current_policy` + `trusted_int(build_edge_policy(...).max_attempts)` |
| `rules/drift.py` D1 | `sourced()` + ручной source | typed-операнд; отсутствующий ключ не подменяется fallback'ами |

Контроль: оба golden-снимка побайтово зелёные, полный пакет C
(17 файлов) зелёный, 415 тестов + 93 сабтеста. Старые имена
`sourced`/`current` из `rules/budget` удалены; `pauses_ns` остаётся
реэкспортом (тест Амира импортирует из rules.budget).

Расхождение, зафиксированное ранее как «сознательное», устранено:
typed-вид и плоские примитивы теперь одна семантика
(`TestSourcedValueSemantics` — эталон).

**Не входило (стена, решение за Амиром):** OBS_RETRIES и R5-статистика —
знаменатели C (исключённые группы, совместимость часов) не совпадают с
`EdgeStats`; требуется аддитивное расширение контракта с его ревью.

## Шаг 2. Единая per-edge статистика: `build_edge_stats` (1–1½ дня)

Что переводим:

1. **OBS_RETRIES** (`context.py: observations`, вызывается из
   `audit.py:119-128`): `retry_calls`, `observed_attempts`,
   `attempts_without_confirmed_group`, `retry_ratio` — заменить
   подсчётом из `EdgeStats` (`attempts`, `eligible_calls`,
   `trace_count`, `attempt_error_ratio`). Внимание: `missing` считает
   попытки вне подтверждённых групп — в `EdgeStats` такого поля нет.
   Два варианта: (а) считать как сейчас одной строкой поверх
   `by_edge`/`by_id`; (б) предложить аддитивное поле через ревью
   контрактов. Рекомендация: (а) в этом шаге, (б) — отдельным мини-PR.
2. **R5** (`diagnostics.py: retry_checks`, часть пауз): статистика пауз
   (`gaps_by_index` — сырые значения по индексам) берётся из
   `EdgeStats.gaps_by_index`; p95/CV/pороги остаются в C (там свои
   `min_cases`/`jitter_min_samples`). Убирается дублирующий сбор
   `gaps` по `gap_before_ns`.
3. **baselines** (`baselines.py: build_reference`): **не мигрируем** в
   этом шаге. Причина: там доменная валидация (запрет смешанных сегментов,
   запрет множественных ревизий одной трассы, min/max длительностей),
   которой в `EdgeStats` нет, а контракты заморожены. Отдельное решение
   позже: либо аддитивные `success_min_ns/success_max_ns` в `EdgeStats`
   (через ревью), либо оставить как есть — цена вопроса одна функция.

## Шаг 3. Идентичность датасета (½ дня, опционально)

Сейчас B и C независимо отвечают на вопрос «тот же датасет?»:
`contribution_digest` (core/model.py) и `data_hash` (audit.py:102).
Оба зелётеют на своих тестах, но право разойтись сохранено.

Решение по факту: если для frozen-сравнений прогонов достаточно текущего
`data_hash` (включает grouping_version и публичные поля модели) — фиксируем
документом эквивалентность и закрываем вопрос. Если Амиру нужна
побайтовая согласованность с B — `data_hash` считается как
`digest([contribution_digest(contributions), thresholds_version])`, а
`RepositoryView` начинает передавать contributions в `run()`. Точка
решения — Амир, до начала шага 3.
