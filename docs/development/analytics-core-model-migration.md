# Типизированная модель аналитики

Аналитика использует типизированные статистику рёбер и политики из
`core/model.py`. Golden-тесты фиксируют публичный вывод аудита, включая
записанный прогон checkout в `sandbox`, при изменении внутренних моделей.

## Границы модели

**Цель:** единая каноническая семантика per-edge статистики и доверия к
конфигу, типизированная вместо соглашений о строковых ключах.

**Не-цели:**
- Не переписываем `flatten_policies` (merge P4-снимков, capabilities,
  external_timeouts) — он остаётся; `build_edge_policy` принимает его вывод.
- Не трогаем `Comparison`/`projection`/`evalkit` — там своя логика когорт.
- Не меняем wire-форматы ответов аудита: находки, evidence, оценки
  правил сериализуются как сейчас.

## Эталонные проверки

`tests/analytics/test_migration_golden.py` сравнивает полный вывод `rules.audit.run()`
на двух синтетических входах и одном записанном прогоне. Фикстура
`audit-sandbox-checkout.json.gz` содержит 30 замороженных трейсов реального
checkout с HTTP 503, снимки политик до применения R4 и исходный вывод аудита.
Фикстура получена на отдельном Compose-стенде через браузер. Синтетические
эталоны обновляются через `GOLDEN_UPDATE=1` с ревью диффа.

## Доверие к политике и `EdgePolicy`

`_operand` в `core/model.py` воспроизводит
семантику `sourced_value` один-в-один (сверка ревизий операнда со снимком;
плоские операнды читаются по источнику снимка независимо от свежести;
форма операнда маркируется в `reasons`). Добавлены `trusted_value` /
`trusted_int`. Пять call-сайтов переведены:

| Файл | Прежнее представление | Текущее представление |
|---|---|---|
| `rules/budget.py` `retry_budget` | `sourced()` ×4 по ключам | `build_edge_policy` + `trusted_int` (max_attempts, per_attempt_timeout_ns); `budget_ns`/`backoff` — канонический `sourced_value` (вне typed-вида) |
| `rules/diagnostics.py` R7 | `sourced(retry_on) if current` | `sourced_value(...)` через `is_current_policy` (список вне typed-вида) |
| `rules/diagnostics.py` R8 | `sourced()` ×2 | typed `per_attempt_timeout_ns` + `sourced_value(upstream_per_attempt_timeout_ns)` |
| `rules/audit.py` R3 | `current()` + `sourced(max_attempts)` | `is_current_policy` + `trusted_int(build_edge_policy(...).max_attempts)` |
| `rules/drift.py` D1 | `sourced()` + ручной source | typed-операнд; отсутствующий ключ не подменяется fallback'ами |

`trusted_value` и `trusted_int` сохраняют семантику `sourced_value`: отсутствие
доверенного значения не подменяется догадкой. `TestSourcedValueSemantics`
и golden-тесты проверяют совместимость представлений.

## Общий сбор статистики по рёбрам

`build_edge_stats`, `OBS_RETRIES` и `R5` используют сборщик
`EdgeRetrySamples` из `core/model.py`. Он считает группы и собирает паузы по
индексам. Каждый потребитель передаёт пригодные по своим правилам наблюдения.

- `OBS_RETRIES` считает подтверждённые serial-группы. Попытки вне
  подтверждённых групп учитываются по индексу членства аудита.
- `R5` добавляет только паузы между соседними CLIENT-попытками с известными
  совместимыми часами. Ссылки на трейсы, причины исключения, p95, CV и пороги
  сохраняются в выводе правила.
- Публичные DTO P3/P5 сохраняют существующие поля и значения. Построение
  baseline остаётся в `rules/baselines.py`, где проверяются сегменты и ревизии.

## Идентичность датасета

`contribution_digest` идентифицирует входы агрегатов Core по TraceRef,
версии группировки и числу попыток. `data_hash` в аудите учитывает также
нормализованные поля попыток и спанов, метки рёбер и sampling. Эти идентификаторы
используются для разных задач. Их унификация отложена до появления требования
к общей идентичности, поскольку смена входа хеша изменит ID находок аудита.

Для проверки изменений запускайте эталонные тесты, `tests/analytics/`,
`tests/test_core_model.py` и проверки Ruff и Mypy из инструкции проекта.
